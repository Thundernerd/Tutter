## The art

Every image in Blast Grid is generated by a small Python script using [Pillow](https://pillow.readthedocs.io/): no drawing skills needed, and you can tweak colours in code. Download the pack: [blast-grid-art.zip](./files/blast-grid-art.zip). It contains the finished PNGs in an `art/` folder plus `make_art.py`, the script that drew them. Unzip it into your project folder, so you have `res://art/tiles.png` and friends.

| File | Contents |
| --- | --- |
| `tiles.png` | Floor, wall and block, 24×24 each |
| `bomber.png` | A 3×3 sheet: walking down, up and sideways |
| `bomb.png`, `flame.png` | A bomb, and three flame pieces (centre, middle, end) |
| `power_ups.png` | Three power-up icons |
| `monster.png` | Two frames of a grumpy balloon |

The tiles are just rectangles and lines. This is the part of the script that draws `tiles.png`:

```python title="make_art.py"
def tiles() -> None:
    """tiles.png: floor, wall, block, side by side."""
    img = Image.new("RGBA", (T * 3, T), (0, 0, 0, 0))
    d = ImageDraw.Draw(img)

    # Floor: green with a slightly darker edge, so the grid is readable.
    d.rectangle([0, 0, T - 1, T - 1], fill=(58, 125, 68))
    d.line([0, T - 1, T - 1, T - 1], fill=(48, 106, 57))
    d.line([T - 1, 0, T - 1, T - 1], fill=(48, 106, 57))
    for x, y in [(5, 6), (16, 15), (9, 18)]:  # a few specks of grass
        d.point((x, y), fill=(74, 146, 84))

    # Wall: grey stone with a bevel: light top-left, dark bottom-right.
    x0 = T
    d.rectangle([x0, 0, x0 + T - 1, T - 1], fill=(132, 138, 156))
    d.rectangle([x0, 0, x0 + T - 1, 2], fill=(190, 196, 212))
    d.rectangle([x0, 0, x0 + 2, T - 1], fill=(190, 196, 212))
    d.rectangle([x0, T - 3, x0 + T - 1, T - 1], fill=(72, 76, 92))
    d.rectangle([x0 + T - 3, 0, x0 + T - 1, T - 1], fill=(72, 76, 92))
    d.rectangle([x0 + 7, 7, x0 + T - 8, T - 8], outline=(104, 110, 128))

    # Block: orange bricks that look breakable.
    x0 = T * 2
    d.rectangle([x0, 0, x0 + T - 1, T - 1], fill=(196, 112, 52))
    mortar = (120, 62, 30)
    for row in range(4):
        y = row * 6
        d.line([x0, y + 5, x0 + T - 1, y + 5], fill=mortar)
        offset = 0 if row % 2 == 0 else 6
        for bx in range(offset, T, 12):
            d.line([x0 + bx, y, x0 + bx, y + 5], fill=mortar)
        d.line([x0, y, x0 + T - 1, y], fill=(226, 150, 86))
    d.rectangle([x0, 0, x0 + T - 1, T - 1], outline=mortar)
    img.save(OUT / "tiles.png")
```

`T` is 24, the tile size. Pillow's rectangles include both corners, which is why you see `T - 1` everywhere. Prefer drawing your own? Any 72×24 image with three 24×24 tiles works.

## Collision layers

Before the TileSet, name the physics layers we'll use in this game: **Project Settings → Layer Names → 2D Physics**. A body's **layer** says what it *is*; its **mask** says what it *looks for*.

| Layer | Name | Used by |
| --- | --- | --- |
| 1 | `solid` | wall and block tiles |
| 2 | `bombs` | bombs |
| 3 | `bombers` | players and CPU bombers |
| 4 | `monsters` | wandering monsters |
| 5 | `flames` | explosions |
| 6 | `power_ups` | power-ups |

Bombers will look for `solid` and `bombs`, so walls, blocks and bombs stop them. They don't look for each other, so bombers walk through one another, just like in the classic games.

## Create the TileSet

1. In the FileSystem dock, right-click → **Create New → Resource…**, pick **TileSet** and save it as `arena_tiles.tres`.
2. In the Inspector, set **Tile Size** to `24 × 24`.
3. Expand **Physics Layers** and click **Add Element**. Set its **Collision Layer** to `solid` only and clear its **Collision Mask**: tiles never move, so they don't need to look for anything.
4. With the TileSet selected, open the **TileSet** panel at the bottom of the editor. Drag `art/tiles.png` into its left-hand list. Godot asks whether to create tiles automatically in the non-transparent regions: say **Yes**.

You now have an **atlas source** (source id `0`) with three tiles. Atlas tiles are identified by their column and row in the image, the **atlas coordinates**:

| Tile | Atlas coords | Collision |
| --- | --- | --- |
| Floor | `(0, 0)` | none |
| Wall | `(1, 0)` | full square |
| Block | `(2, 0)` | full square |

## Tile collision

Collision belongs to the tile, so every wall you paint later is automatically solid.

In the TileSet panel, switch to **Paint**. Under **Paint Properties** choose **Physics Layer 0**. A polygon editor appears. Choose **Reset to default tile shape** from the menu at the right end of its toolbar to get a polygon covering the whole tile. Now click the **wall** and **block** tiles in the atlas to paint that polygon onto them. Leave the floor alone.

A TileSet is a resource like any other, saved as text. Yours should look much like this:

```ini title="arena_tiles.tres"
[gd_resource type="TileSet" load_steps=3 format=3]

[ext_resource type="Texture2D" path="res://art/tiles.png" id="1"]

[sub_resource type="TileSetAtlasSource" id="atlas"]
texture = ExtResource("1")
texture_region_size = Vector2i(24, 24)
0:0/0 = 0
1:0/0 = 0
1:0/0/physics_layer_0/polygon_0/points = PackedVector2Array(-12, -12, 12, -12, 12, 12, -12, 12)
2:0/0 = 0
2:0/0/physics_layer_0/polygon_0/points = PackedVector2Array(-12, -12, 12, -12, 12, 12, -12, 12)

[resource]
tile_size = Vector2i(24, 24)
physics_layer_0/collision_layer = 1
physics_layer_0/collision_mask = 0
sources/0 = SubResource("atlas")
```

`1:0/0` reads as *atlas coords (1, 0), alternative 0*. The polygon points are relative to the tile's centre, so ±12 covers all 24 pixels.

:::tip[Custom data layers]
A TileSet can also store your own per-tile values: **Custom Data Layers** in the Inspector, then paint them like collision. Footstep sounds, damage floors or "slippery ice" all fit there. Blast Grid doesn't need any, because walls and blocks live on separate layers, as you'll see next.
:::
