## The sounds

Download the pack: [blast-grid-sounds.zip](./files/blast-grid-sounds.zip). Unzip it into the project so you have a `sounds/` folder; Godot imports `.wav` files automatically.

| File | Plays when |
| --- | --- |
| `place.wav` | a bomb is placed |
| `explosion.wav` | a bomb explodes |
| `power_up.wav` | a power-up is collected |
| `death.wav` | a bomber dies |
| `thud.wav` | a sudden-death wall lands |
| `round_end.wav` | a round ends |

Like the art, they're generated by a script, `make_sounds.py`, included in the zip and using only Python's standard library: square waves for the blips and filtered noise for the explosion. The explosion is random noise passed through a filter that gets darker as it fades:

```python title="make_sounds.py"
def explosion():
    n = int(RATE * 0.6)
    out, low = [], 0.0
    for i in range(n):
        t = i / n
        low += (random.uniform(-1, 1) - low) * (0.25 - 0.2 * t)  # darker as it fades
        out.append(low * 2.2 * (1 - t) ** 2)
    return out
```

`low` follows the noise slowly (a *low-pass filter*), and the smaller the factor, the slower it follows and the duller the sound. Want different sounds? [jsfxr](https://sfxr.me) makes retro effects in the browser.

## Players

Add a plain `Node` named `Sounds` to `game.tscn` with six `AudioStreamPlayer` children, one per sound, all on the **SFX** bus:

| Node | Stream | Max Polyphony |
| --- | --- | --- |
| `Place` | `place.wav` | 1 |
| `Explosion` | `explosion.wav` | **4** |
| `PowerUp` | `power_up.wav` | 1 |
| `Death` | `death.wav` | 1 |
| `Thud` | `thud.wav` | **2** |
| `RoundEnd` | `round_end.wav` | 1 |

**Max Polyphony** is how many copies of the sound one player can play at once. With the default of 1, calling `play()` again restarts the sound. A chain reaction of five bombs in one frame would then sound like a single explosion that keeps getting cut off. With 4, the blasts layer up.

Also give the options screen's `TestSound` the `power_up.wav` stream, so dragging the effects slider has something to play.

## Wiring

```gdscript title="game.gd" ins={3-4,9-10}
func _ready() -> void:
	# ...
	arena.exploded.connect(_on_arena_exploded)
	arena.wall_dropped.connect(_on_wall_dropped)
	round_timer.start()

# In _spawn_bombers:
		bomber.died.connect(_on_bomber_died)
		bomber.bomb_placed.connect($Sounds/Place.play)
		bomber.powered_up.connect(_on_bomber_powered_up)
```

```gdscript title="game.gd"
func _on_arena_exploded(_cells: Array[Vector2i]) -> void:
	$Sounds/Explosion.play()


func _on_wall_dropped(_cell: Vector2i) -> void:
	$Sounds/Thud.play()


func _on_bomber_powered_up(_kind: PowerUp.Kind) -> void:
	$Sounds/PowerUp.play()
```

Plus a `$Sounds/Death.play()` at the start of `_on_bomber_died` and a `$Sounds/RoundEnd.play()` in `_end_round`, right after `Match.finish_round(winner)`.

`$Sounds/Place.play` without parentheses is a **Callable**: a reference to the method. When the signal and the method have matching arguments (here, none), you can connect them directly without a wrapper function. `powered_up` passes the kind, which `play()` doesn't take, so it gets a small handler.

:::note[AudioStreamPlayer vs AudioStreamPlayer2D]
`AudioStreamPlayer2D` gets quieter and pans with distance from the camera. On a single-screen arena where the camera never moves, that would only make the corners quieter, so plain `AudioStreamPlayer`s are the better fit.
:::
